# Option C pilot protocol: point-level cross-frame reproduction audit ("framecheck")

**Written:** 2026-10-07 ~09:16 HST (corrected from a hand-typed "~09:30"; file evidence: catalog cached 09:16:30, first mesh tif fetched 09:16:55), BEFORE any mesh x/y/z.tif was downloaded for this pilot. Only `metadata.json` (catalog) has been read so far.

## Question
Each published `mesh/<id>-on-<vol>-<um>.tifxyz` marked `tifxyz-transformed` with process `transform-tifxyz-normalized` was made by carrying the segment's `mesh/intermediate/tifxyz_normalized/` (in the original volume frame) into the target volume's frame. Does applying the **current** catalog matrix (`samples[s].sample.properties.volume_transforms[original→target].matrix`) to the normalized mesh reproduce the published transformed mesh **point by point**? We report the answer in target voxels and in µm (× target volume `pixel_size_um`).

Why it matters: anyone moving their own points (labels, annotations, fiber traces) between frames uses the catalog matrix. If published meshes don't match the current catalog, then the meshes or the catalog changed after the fact, and conversions silently disagree with the published geometry. Prior work only checked this at **bbox-centre** level with a 5%-of-extent tolerance (villa #1468, 3 scrolls) or by declared corners (#1843 says it did not compare point by point).

## Inputs (fixed)
- Catalog: `data/cache/metadata-2026-10-07.json` (fetched 2026-10-07 09:14 HST).
- Matrix convention to test: 3×4 affine on [x, y, z, 1] (tifxyz x.tif, y.tif, z.tif order). This matches the landmark order in the catalog (third component spans the Z extent of the volume shape). If both conventions fail on every mesh, report "convention unknown" and do not tune further.
- Valid cell: x, y, z all finite and not −1 in **both** meshes. Also report validity-mask mismatches.

## Sample (deterministic, data-blind)
- Every sample that has `transform-tifxyz-normalized` meshes (9 scrolls).
- Per sample: the first 4 segments by segment id that have a `tifxyz-normalized` entry. Include all of their `tifxyz-transformed` meshes (both `transform-tifxyz-normalized` and `copy-normalized-for-original`).
- Controls:
  - (a) `copy-normalized-for-original` meshes should equal normalized (identity).
  - (b) target == original volume (no catalog matrix; 112 corpus-wide) should equal normalized (identity).

## Metric and frozen classes
- r = ‖T·p_norm − p_pub‖ per valid cell, in target voxels. Report median, p99, and max, in voxels and µm.
- **CONSISTENT:** p99 ≤ 0.5 voxel.
- **DRIFT:** median > 1 voxel.
- **PARTIAL:** anything else.
- **NOT_COMPARABLE:** grid shapes differ.

## What would count as a finding
- Any DRIFT/PARTIAL mesh, with its sample, target volume and size (µm).
- If everything is CONSISTENT: a verified statement that, for the sampled scrolls, the published meshes are exactly the catalog matrices applied to the normalized mesh. It follows that any error in a catalog matrix (#1835/#1843) is inherited by every derived mesh. Thresholds will not be tuned after seeing data.

## Diagnostic (added before download; does not change any class)
- 105 segments declare `original_volume_downscale` = 4 and 7 declare 2. For every mesh we also fit a least-squares affine from normalized to published points (strided ≤ 50k valid cells). We report its residual and how far it is from the catalog matrix (e.g. a pure scale equal to the downscale). This is only to *describe* a mismatch. Classes still use the catalog matrix as-is.

## Amendment A1 (2026-10-07 09:25:43 HST per file mtime; corrected from a hand-typed "~09:55"; after the index-level run, BEFORE any cross-frame residual was computed)
- Index-level run result: every identity control (35/35) is CONSISTENT at exactly 0 voxels. Every cross-frame mesh (69/69) is NOT_COMPARABLE: grid shapes differ.
- Cause, read from villa source @ e0bbb8b4: `vc_transform_geom` → `transformSurfacePoints` applies the affine, then regrids the surface by the measured spacing ratio. That is `QuadSurface::resample` → `resamplePointsLinearPreservingInvalids`: half-pixel-centre bilinear, skipping any 2×2 block with an invalid corner. `meta.scale` is then reset to its original value (this is why scale stays 0.05; #1522).
- An affine map commutes with bilinear interpolation. So the reproduction prediction is **T(s · resample(P_norm → published shape))**, with s = `original_volume_downscale`. This is the same pre-scale VC3D's open-data loader applies (`OpenDataSegmentCache.cpp:496`). Resampling uses the exact source formula and the published grid shape. No other parameters are fitted.
- Caveat: the pipeline ran at villa commit 650bd566, not e0bbb8b4. If resampling code differed then, residuals would show it. We will report it, not tune.
- Classes and thresholds are unchanged (CONSISTENT p99 ≤ 0.5 vox; DRIFT median > 1 vox; else PARTIAL).

## Amendment A2: full corpus run with the xframe package (2026-10-07 09:39 HST, written while the run was in progress, before any summary of it was computed)
- Code: `xframe/` v0.1.0, installed non-editable in a clean venv (/tmp/xframe-venv). 19/19 tests passed, including 3 live-bucket tests (`out/xframe-pytest-clean-venv-2026-10-07.log`). Driver: `scripts/full_verify.py`, 3 workers, anonymous HTTPS, no payload cache. Catalog snapshot: `data/cache/metadata-2026-10-07.json`.
- Differences from the pilot:
  - VC order is followed literally: affine on the source first, then the VC spacing-ratio regrid. The predicted grid shape is computed from the source alone (port of `measureGridAxisSpacing` + `round(n·factor)`), so shape agreement is now an independent check.
  - Classes are decided from exact exceedance counts: CONSISTENT iff ≤1% of cells > 0.5 vox; DRIFT iff >50% of cells > 1 vox. These match the frozen quantile thresholds apart from interpolation ties.
  - Reported median/p99 are the upper edges of log bins (≤0.115% relative width). Max is exact.
- Scope: every segment with a `tifxyz-transformed` mesh: 707 `transform-tifxyz-normalized` + 195 `copy-normalized-for-original`. This includes all downscale segments (PHercParis4 ×4: 204 meshes; PHerc0139 ×4: 189; PHerc0500P2 ×2: 21).
