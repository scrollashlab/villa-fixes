# villa #1522 — mesh `meta.json` scale does not distinguish frames

Upstream: https://github.com/ScrollPrize/villa/issues/1522  
Evidence: `villa-1522/`  
Author on patch: Scroll Ash Lab \<scrollash.lab@gmail.com\> (AI-assisted)

## Problem

`meta.json` `"scale"` means grid cells per voxel of **that mesh’s own scan**. Segments often ship several meshes that all declare nearly the same `scale` (e.g. `0.05`) while voxel sizes in the directory name differ by up to ~40×. Consumers that treat matching `scale` as “same frame” silently mix coordinates.

## What changed

- Document the trap in `vesuvius/tifxyz/API.md`.
- Optional `voxel_size_um` on `meta.json` (reader/writer first-class).
- `vesuvius.tifxyz.meta_frames`: parse `-<float>um` from directory names, annotate metas, detect same-scale / different-voxel-size groups, `frames_comparable()`.
- Scale equality: `math.isclose` with **`SCALE_RTOL=1e-6`** (`SCALE_ATOL=0`).

Does **not** change C++ writers (they still omit the field until updated). Does **not** auto-fix the public bucket.

Related: `villa-tifxyz-audit/` / `tools/tifxyz-audit/` CLI (apply **after** this patch).

### Float-tolerance caveat

Open-data metas mix JSON `0.05` with float32→float64 `0.05000000074505806` (rel ≈ **1.49e-8**). Exact-float builds of this patch missed Paris4’s 7.91 meta and falsely rejected PHerc0172 twins. `1e-6` is ~67× that gap and still far tighter than intentional steps (e.g. 0.05 vs 0.1). Covered by regression tests using the observed floats.
